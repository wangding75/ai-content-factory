# Iteration 8：数据录入与指标看板

> 文件定位：本文件是迭代 8 的需求评审与开发范围文档。  
> 蓝图约束：本迭代必须遵守 `00-product-blueprint.md`。  
> 开发规则：进入开发前必须完成本文件中的需求评审检查。

---

## 1. 迭代目标

建立通用 MetricRecord 指标中心，并先支持 Novel Pack 的阅读、书架、留存、完读率数据。

---

## 2. 蓝图对齐说明

| 蓝图约束 | 本迭代对齐方式 |
|---|---|
| 核心平台内容类型无关 | 本迭代不得把小说专属逻辑写入 Core |
| 内容类型插件化 | Novel 相关能力必须放入 Novel Pack 或扩展模型 |
| 工作流可配置 | 涉及流程时必须通过 WorkflowTemplate / WorkflowRun 承载 |
| Agent 可追踪 | 涉及 Agent 时必须记录 AgentTask 和 LLMCallLog |
| 发布平台适配器化 | 涉及发布时必须通过 PublishJob / PlatformAdapter 承载 |
| 指标通用化 | 涉及数据时必须通过 MetricRecord / MetricTemplate 承载 |
| 人工节点保留 | 审稿、发布、策略等关键动作必须支持人工确认 |
| 迭代可评审 | 开发前必须完成需求评审与验收标准确认 |

---

## 3. 产品需求

- 支持手动录入书级指标。
- 支持手动录入章节级指标。
- 支持展示项目健康状态。
- 支持展示阅读、书架、留存、完读率趋势。
- 支持数据缺失提醒。

---

## 4. 技术需求

- 实现 MetricRecord。
- 实现 MetricTemplate。
- 实现指标录入页面。
- 实现趋势计算。
- 实现图表组件。
- 实现数据缺失检测。

---

## 5. 涉及数据模型

- `metric_record`
- `metric_template`

---

## 6. 涉及 Agent / 工作流

- 暂不实现 PerformanceAgent，先用规则计算。

---

## 7. 验收标准

- [ ] 可以录入 Novel 项目的日阅读量、加书架数、留存率。
- [ ] 可以录入章节完读率。
- [ ] 可以查看 7 天 / 14 天趋势。
- [ ] 可以识别数据缺失日期。
- [ ] MetricRecord 支持 metric_name / metric_value / platform / source 等通用字段。
- [ ] 看板指标配置不写死为小说专属逻辑。

---

## 8. 需求评审检查项

- [ ] MetricRecord 是否能支持文章阅读量、小红书收藏、短视频完播率？
- [ ] Novel 指标是否通过模板配置？
- [ ] 数据来源是否支持手动、插件、API 三类？
- [ ] 指标口径是否清晰？

---

## 9. 本迭代明确不做

- 不做自动采集。
- 不做复杂 BI。
- 不做自动策略执行。

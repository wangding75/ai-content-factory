# Iteration 10：Project Portfolio 多项目管理

> 文件定位：本文件是迭代 10 的需求评审与开发范围文档。  
> 蓝图约束：本迭代必须遵守 `00-product-blueprint.md`。  
> 开发规则：进入开发前必须完成本文件中的需求评审检查。

---

## 1. 迭代目标

从单项目闭环升级为多内容项目组合管理，支持资源分配、优先级和成本对比。

---

## 2. 蓝图对齐说明

| 蓝图约束 | 本迭代对齐方式 |
|---|---|
| 核心平台内容类型无关 | 本迭代不得把小说专属逻辑写入 Core |
| 内容类型插件化 | Novel 相关能力必须放入 Novel Pack 或扩展模型 |
| 工作流可配置 | 涉及流程时必须通过 WorkflowTemplate / WorkflowRun 承载 |
| Agent 可追踪 | 涉及 Agent 时必须记录 AgentTask 和 LLMCallLog |
| 发布平台适配器化 | 涉及发布时必须通过 PublishJob / PlatformAdapter 承载 |
| 指标通用化 | 涉及数据时必须通过 MetricRecord / MetricTemplate 承载 |
| 人工节点保留 | 审稿、发布、策略等关键动作必须支持人工确认 |
| 迭代可评审 | 开发前必须完成需求评审与验收标准确认 |

---

## 3. 产品需求

- 支持多个 ContentProject 统一管理。
- 支持多项目健康状态对比。
- 支持项目优先级。
- 支持低表现项目降频或暂停建议。
- 支持高表现项目加仓建议。
- 支持按项目查看成本。

---

## 4. 技术需求

- 实现 ProjectPortfolio。
- 实现多项目调度优先级。
- 实现并发控制。
- 实现成本按项目分摊。
- 实现项目组合看板。
- 扩展 LLMCallLog 成本统计。

---

## 5. 涉及数据模型

- `project_portfolio`
- `portfolio_project`
- `cost_summary`

---

## 6. 涉及 Agent / 工作流

- PerformanceAgent 接口预留
- StrategyAgent 增强

---

## 7. 验收标准

- [ ] 可以把多个 Novel 项目加入同一个 Portfolio。
- [ ] 可以比较多个项目的阅读、留存、完读、成本。
- [ ] 可以设置项目优先级。
- [ ] 低优先级项目不会阻塞高优先级项目生成。
- [ ] 可以按项目查看 LLM 成本。
- [ ] Portfolio 设计支持未来 Article / Social Post 项目混合管理。

---

## 8. 需求评审检查项

- [ ] ProjectPortfolio 是否不限于多书，而是多内容项目？
- [ ] 调度规则是否可配置？
- [ ] 成本统计是否来自 LLMCallLog？
- [ ] 是否避免某一个项目失败阻塞整体任务？

---

## 9. 本迭代明确不做

- 不做完全自动资源调度。
- 不做跨平台自动投放。
- 不做复杂财务模块。

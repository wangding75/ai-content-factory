# Iteration 5：审稿与质量控制

> 文件定位：本文件是迭代 5 的需求评审与开发范围文档。  
> 蓝图约束：本迭代必须遵守 `00-product-blueprint.md`。  
> 开发规则：进入开发前必须完成本文件中的需求评审检查。

---

## 1. 迭代目标

建立通用内容审核流程，并完成 Novel 章节审稿场景。

---

## 2. 蓝图对齐说明

| 蓝图约束 | 本迭代对齐方式 |
|---|---|
| 核心平台内容类型无关 | 本迭代不得把小说专属逻辑写入 Core |
| 内容类型插件化 | Novel 相关能力必须放入 Novel Pack 或扩展模型 |
| 工作流可配置 | 涉及流程时必须通过 WorkflowTemplate / WorkflowRun 承载 |
| Agent 可追踪 | 涉及 Agent 时必须记录 AgentTask 和 LLMCallLog |
| 发布平台适配器化 | 涉及发布时必须通过 PublishJob / PlatformAdapter 承载 |
| 指标通用化 | 涉及数据时必须通过 MetricRecord / MetricTemplate 承载 |
| 人工节点保留 | 审稿、发布、策略等关键动作必须支持人工确认 |
| 迭代可评审 | 开发前必须完成需求评审与验收标准确认 |

---

## 3. 产品需求

- 支持待审稿列表。
- 支持查看章节正文和生成信息。
- 支持通过、打回、编辑后通过。
- 支持 AI 质检报告。
- 支持保存人工修改版本。

---

## 4. 技术需求

- 实现内容审核状态机。
- 实现 ReviewAgent。
- 实现内容版本快照。
- 实现质检报告结构化存储。
- 实现打回原因和重新生成指令注入。

---

## 5. 涉及数据模型

- `content_review`
- `content_version`
- `review_report`

---

## 6. 涉及 Agent / 工作流

- ReviewAgent

---

## 7. 验收标准

- [ ] 章节生成完成后进入待审稿状态。
- [ ] 运营者可以通过章节，使其进入待发布状态。
- [ ] 运营者可以打回章节并填写原因。
- [ ] 运营者可以编辑正文并保存新版本。
- [ ] AI 质检报告包含逻辑、节奏、爽点、钩子等评分。
- [ ] 审稿状态流转有操作日志。

---

## 8. 需求评审检查项

- [ ] 审稿流程是否通用到文章、短视频脚本？
- [ ] 人工编辑是否保留版本记录？
- [ ] ReviewAgent 是否作为通用 Agent，而不是 Novel 专属？
- [ ] 打回后是否能追踪原因和重新生成参数？

---

## 9. 本迭代明确不做

- 不做合成读者。
- 不做复杂投票。
- 不做自动发布。

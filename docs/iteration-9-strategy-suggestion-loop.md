# Iteration 9：策略建议与单类型业务闭环

> 文件定位：本文件是迭代 9 的需求评审与开发范围文档。  
> 蓝图约束：本迭代必须遵守 `00-product-blueprint.md`。  
> 开发规则：进入开发前必须完成本文件中的需求评审检查。

---

## 1. 迭代目标

根据指标数据输出策略建议，完成 Novel Pack 的生成、审稿、发布、数据、策略闭环。

---

## 2. 蓝图对齐说明

| 蓝图约束 | 本迭代对齐方式 |
|---|---|
| 核心平台内容类型无关 | 本迭代不得把小说专属逻辑写入 Core |
| 内容类型插件化 | Novel 相关能力必须放入 Novel Pack 或扩展模型 |
| 工作流可配置 | 涉及流程时必须通过 WorkflowTemplate / WorkflowRun 承载 |
| Agent 可追踪 | 涉及 Agent 时必须记录 AgentTask 和 LLMCallLog |
| 发布平台适配器化 | 涉及发布时必须通过 PublishJob / PlatformAdapter 承载 |
| 指标通用化 | 涉及数据时必须通过 MetricRecord / MetricTemplate 承载 |
| 人工节点保留 | 审稿、发布、策略等关键动作必须支持人工确认 |
| 迭代可评审 | 开发前必须完成需求评审与验收标准确认 |

---

## 3. 产品需求

- 支持根据指标生成 keep / optimize / suspend / promote 建议。
- 支持运营者查看策略建议原因。
- 支持人工确认执行或忽略。
- 支持记录策略执行结果。
- 支持基础状态变更，例如停更、加更、优化。

---

## 4. 技术需求

- 实现 StrategySuggestion。
- 实现规则引擎。
- 实现 StrategyAgent 的接口预留。
- 实现人工覆盖机制。
- 实现策略操作日志。
- 实现项目状态流转。

---

## 5. 涉及数据模型

- `strategy_suggestion`
- `strategy_rule`
- `project_status_log`

---

## 6. 涉及 Agent / 工作流

- StrategyAgent 可先作为规则包装器，不做复杂 AI 决策。

---

## 7. 验收标准

- [ ] 留存率低于阈值时生成 suspend 建议。
- [ ] 留存率中等时生成 optimize 建议。
- [ ] 留存率高时生成 promote 建议。
- [ ] 运营者可以确认、忽略或备注策略建议。
- [ ] 策略执行后有操作日志。
- [ ] 策略系统不自动执行高风险动作，必须保留人工确认。

---

## 8. 需求评审检查项

- [ ] 策略建议是否基于通用 StrategySuggestion？
- [ ] Novel 阈值是否作为内容类型规则，而不是写死在 Core？
- [ ] 是否保留人工覆盖？
- [ ] 是否形成完整业务闭环？

---

## 9. 本迭代明确不做

- 不做自动停更。
- 不做自动重开。
- 不做 AI 自主运营。

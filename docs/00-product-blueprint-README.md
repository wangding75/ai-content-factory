# 产品蓝图说明

## 文件说明

| 文件 | 说明 |
|---|---|
| `00-product-blueprint.md` | AI Content Factory 项目最高层蓝图 |
| `iteration-README.md` | 迭代总览和蓝图追踪关系 |
| `iteration-*.md` | 每个迭代的独立需求评审文档 |

## 使用规则

1. 所有迭代评审必须先阅读 `00-product-blueprint.md`。
2. 迭代文档中的产品需求、技术需求、验收标准不得背离蓝图。
3. 若迭代中发现蓝图不合理，应先评审和更新蓝图，再调整迭代。
4. 不允许在核心平台中写死 Novel / Book / Chapter 等小说专属概念。
5. 小说能力必须放在 Novel Pack 中实现。
6. 新内容类型应通过 Content Pack 扩展。
7. 新平台应通过 Platform Adapter 扩展。
8. 新指标应通过 MetricRecord 扩展。

## 评审顺序

```text
阅读产品蓝图
  ↓
阅读 iteration-README.md
  ↓
进入具体 iteration-x-*.md
  ↓
完成需求评审
  ↓
完成技术评审
  ↓
进入开发
  ↓
验收并回填结论
```

## 蓝图修改原则

当业务方向发生重大变化时，优先修改蓝图，而不是直接修改某个迭代文档。

需要修改蓝图的典型情况：

| 情况 | 是否修改蓝图 |
|---|---|
| 新增内容类型，例如课程、播客 | 是 |
| 新增平台，例如视频号、TikTok | 是 |
| 核心数据模型变化 | 是 |
| 只是调整某个页面字段 | 否 |
| 只是优化某个 Agent Prompt | 否 |
| 只是修改某个迭代验收标准 | 否，除非影响蓝图约束 |
